## CI cache ownership regression

`FeedbackBaselineCacheTest` could fail after a successful restore was rejected by its catalog digest: Docker copied the archive with a different filesystem owner, and the subsequent `pg_dump` reused `/tmp/epoch-baseline.dump`. A runner's sticky-directory protections can reject that overwrite. Each dump and restore now owns a separate private temporary directory, removed afterward; archive validation and immutable publication are unchanged.

`BaselineCacheOwnershipTest` reproduces the exact Permission denied failure by running actual PostgreSQL tools as a different filesystem user, without changing host kernel settings. After the fix, it proves MISS → valid restore/catalog rejection → REBUILT → HIT, preserved baseline data, excluded pending state and temporary-file cleanup. The focused run passed all 414 core tests and five Docker cache tests, including the originally reported failure, warm-reader concurrency, baseline-plan caching and CLI diagnostics. The subsequent full suite passed on `8e925d2`: 797 tests, zero failures, errors or skips, including the ownership regression and the original cache test.
